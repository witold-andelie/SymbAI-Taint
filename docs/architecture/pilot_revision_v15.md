# Development revision v15: complete fixed three-stage baseline

Declared before implementation/measurement on 11 November 2026. V14 found complementary
capabilities but its two 2/3 methods resolved different queries. Retain its original
sources/results. This revision builds an actually executed strong non-neural control
using the same three known authored mechanisms, not a new data set or held-out study.

## Fixed comparison

Compare exactly two methods: `expanded_only` and `fixed_cascade`, with the latter running
interval, finite-readonly, then expanded checking. Stop on a freshly validated decisive
query result; continue after unknown or a failed attempt, within one shared query budget.
Every attempt starts at the same function entry; reuse no abstract facts, path snapshots,
solver state or previous result across operations/queries/methods/repetitions.

Keep the existing checkers, cap32, max128 instructions, property contract, exclusion guards,
literal reference and frozen A-D selector unchanged. This is a separately versioned
baseline, not an extension of the measured v14 runner. Use only copied v14 binary/query
inputs and copy offline expected outcomes without parsing them until evaluation. Accept
all three identities; no old method/reference result supplies a runtime feature.

Three predeclared repetitions produce 18 method/query records. Rotate query order by
repetition; alternate the two method orders by query-position plus repetition parity.
Each starts in an isolated cold process with a 30 s parent-owned budget. The three
unique inputs remain the denominator; repetitions are not independent samples. No new
programs, compiler, model inference, neural predictions, learning, packages, downloads,
API calls or GPU are involved. All outputs/caches remain on D.

## Evidence and cost boundary

Record the full attempted sequence and preparation, execution, fresh validation, failure
and recording costs. A failed cheap check is paid even if a later check succeeds. Only
validated on-time conclusions can stop the cascade. Keep unsupported/timeout/incomplete
outcomes as unknown, preserve late candidate evidence and retain all 18 planned records.
Runtime requests reject labels, neural inputs, precomputed evidence and unexpected fields.

The parent clock begins before request serialization and process launch. It includes
startup/imports, all operation attempts and validation, flushed events, worker result
serialization, process cleanup, parent recovery and detailed trial payload persistence.
Only the final small accounting receipt, aggregate copying and offline evaluation lie
outside this clock; explicitly report these exclusions. Do not call a stage sum a complete
cost or assume that final receipt serialization is free deployment work. A late parent
result is unknown even if the worker originally returned a decisive result. Emit actual
Python/executable and dependency-version metadata per worker, including version-lookup
overhead, to close v14's per-worker provenance limitation.

After all 18 method workers finish, obtain three fresh, separate label-free references
using v14's literal-BVV/symbolic reference helper. Do not reuse prior measured references
or make them free runtime inputs. Parse the copied offline labels only after references
finish. Unsupported or unresolved references and any wrong decisive result block
scientific interpretation. Record source/input/copy hashes before use and recheck them.

## Evaluation

Report query IDs/status vectors, stable correct coverage per unique query and repetitions,
wrong/unknown counts and attempted operations. Separate comparisons into same correct
resolved query, cascade-only resolution, full-only resolution, both unknown, failure and
disagreement. Report actual cost pairs only on the same correctly resolved query identities;
do not infer speed from equal aggregate counts or different resolved subsets. Keep every
paired trial, including the first, and describe timing variation rather than asserting
significance/stable speed from three developer repetitions.

If the cascade resolves all three correctly, establish that concrete strong baseline.
This does not establish neural guidance, algorithm novelty, generalization or native proof.
Any later neural selector must surpass this fixed baseline as well as structural/cardinality
routing under declared budgets. Preserve the v13 negative result; do not introduce a new
type score in this revision. Update the OPM view, tests, audit and evidence before WSL
replication. All test processes must exit before measured runs start.
