# Development revision v13: routing sensitivity before another execution study

Declared before this implementation/diagnostic on 11 November 2026. The three existing
compiled integration inputs and their predictions are already known development data;
this is not a preregistration on unseen inputs or an independent evaluation. V11 found
no useful execution-work difference between depth limits, and v12 closed the restricted
location-only interface. Keep their original sources/results and the frozen A-D runner.

## Question and fixed menu

Before another expensive budgeted execution study, can genuine type views change the
operation order of a simple shared property-directed selector beyond a strong structural
preference? Use only the same three frozen binary/query/raw-export inputs, without new
compilation, model inference, training, examples, packages, APIs or GPU work.

The fixed alternative analyses are the existing restricted `frame_bounds` checker and
`expanded_paths` checker. These have distinct capabilities: the first can prove some
straight-line frame interval exclusions; the second checks modeled first-visit paths and
can produce witnesses. Merely lowering a path-depth cap or preparing RDA is not an extra
operation. This stage selects/orders operations but **does not execute either checker**.
It cannot report new property decisions, budgeted results or speedup.

## Shared policy, structural baseline and type signal

Acquire only type-blind static canonical-frame syntax features from binary/query bytes,
using the v12 static walker without raw predictions. Expose availability, instruction
count, address-load count and presence of a supported immediate `and` instruction. This
mask cue is a routing preference, not a proof that the mask establishes the property.
Do not read query IDs, source names, offline labels or prior operation outcomes to score.

Use one policy function and identical candidates, tie-break and structural features for
B/C/D. Full checking has score 1.0. Frame checking has structural score 1.25 when the
static walk is supported and an immediate mask is present, otherwise 0.75 if supported
or 0.0 if unsupported. A fixed frame-first order and full-first order are reported as
controls. No action is removed by types, and the existing frozen selector is unchanged.

For C/D, bind raw predictions with the v12 location-only mapper. C supplies independent
Top-1 labels without scores; D supplies each occurrence's original Top-K logits and
conditional weights. Define an explicitly heuristic contributor-mixture support in [0,1]:
the maximum, over distinct load occurrences i,j, of the minimum of pointer-label support
at i and integer-label support at j. B has no type contribution. This aggregate assigns
no base/index roles, merges no raw candidate records and is not a joint probability or
semantic fact. It is an initial interpretable routing heuristic, not an algorithm novelty
claim, calibrated utility prediction or general characterization of neural guidance.
Pointer labels contain `*`; integer labels are `bool`, `char`, `int`, `size_t` or the
TYGR signed/unsigned integer widths, and must not be pointer labels. Aggregate/array/
opaque labels receive neither kind of support. Do not reuse the old selector's overlapping
label classifier. Distinct occurrences need not be statistically independent; retain their
prediction IDs and make no independence claim.

Add `type_weight * mixture_support` to the frame score. Primary weight is 0.5; report the
entire fixed grid [0, 0.25, 0.5, 1, 2], including zero. Never select a weight by an observed
query result or best-looking run. Ties break by operation ID. An unknown first check would
fall back to the remaining operation; therefore identical complete orders imply identical
action sequences for this two-operation policy, given equal checker outcomes and stop rules.
No runtime claim follows from that order comparison alone.
The score geometry is known before measurement: supported masked inputs always stay
frame-first for nonnegative weights; supported unmasked inputs can switch only when
`weight * mixture_support > 0.25`. The zero/0.25 grid points cannot change an order.
Report these thresholds and do not treat structurally forced agreement as general evidence
against neural information. A zero unmasked type signal implies invariance at all finite
nonnegative weights for this particular policy, not for other schedulers.

## Isolation, records and next decision

The type-blind features are acquired before loading raw candidates. B must not receive or
read a type view. Failure to build C/D correspondence or candidates retains that arm as
unavailable, rather than silently replacing it with B or dropping the input. Validate
input/source hashes and preserve original raw bytes. No old semantic bundle/plan/proof,
offline label or prior query outcome enters the runtime. Keep all three case identities.

Record shared policy/features hashes, operation scores and complete orders for B/C/D
at every grid weight, independent per-occurrence projections, unavailable reasons,
source/input provenance and measured feature/mapping/projection/selection/recording costs.
These are routing diagnostic costs from frozen exports, excluding historical neural
acquisition and command startup; never present them as end-to-end comparison or free
deployment features. Include a clean-process check that no angr/Claripy/Z3/property checker
or semantic mapper was imported. All output/cache paths remain on D.

Test that structural features and policy/non-type inputs are shared, genuine score/label
changes can alter decisions on fabricated inputs, wrong mapping identities are rejected,
C hides scores, unknowns/failures survive and semantic/gold inputs cannot enter. Audit
the real records independently after all unit tests exit. Update the OPM view and evidence.

If all real B/C/D orders agree, conclude only that this heuristic has no routing difference
on these three known inputs, across this grid. Do not run redundant property checks to
claim benefit, train a selector on the same inputs, tune weights until a difference appears,
or conclude all neural schedulers are useless. If orders differ, identify the exact type
signal responsible; a later declared, budget-matched execution study must still show that
the change is useful and pays for acquisition. RQ1/RQ2, the 12-mechanism primary denominator,
three-input integration panel and hardware limits remain unchanged.
