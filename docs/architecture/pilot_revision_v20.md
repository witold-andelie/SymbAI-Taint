# Development revision v20: native readout-to-address-load correspondence

Declared on 12 November 2026 after the audited v19 capture and before implementation
or collection for this revision. Preserve the original v19 captures, sources, tensors,
query/model identities, row order and encoder erratum. RQ1/RQ2 and B/C/D stay frozen.

## Fixed evidence and scope

Use only the three captured compiled integration inputs: direct_index, offset_index
and masked_index. Reuse their v19 native captures without new inference/generation,
compilation, solver, installation, GPU or API. No new samples or v17 projections. All
workspace outputs/caches stay on D. Main agent reviews delegated code/findings.

Recheck original input/source/payload/budget identities using the v19 audit. For the
correspondence runtime, project the original query to exactly binary/hash, function entry
and target write RVAs plus the native capture fingerprint. Do not forward object bounds,
input ranges, expected answers, old predictions/logits, old role proofs or model labels.

Freshly decode the restricted straight-line AMD64 canonical frame subset using the
existing v12 static walker. Its memory-load origins contributing to the target write
address are syntax dependencies, not verified semantic base/index roles. Reuse its
implementation without changing its frozen semantics. No program property is solved.

## Separate association from event proof

Associate an address-contributing stack-load occurrence with a native original variable
group only if function identity, unique CFA location, eight-byte load width and location
lifetime covering both load and use agree. Match physical metadata, never variable names,
prediction labels, exporter ID strings, sampled data values or group/row order across runs.
Bind row indices to the exact v19 capture fingerprint; graph IDs from other acquisitions
are not comparable. Preserve complete original group order and flattened row partitions.
Missing, malformed, overlapping or ambiguous locations remain unavailable.

For each associated group retain every native row, annotation address, incoming mem_loc/
reg_loc provenance and whether its address coincides with the actual static load PC.
Preserve every group member, including nodes attributed to earlier stores/other accesses.
Do not select only the matching row or recompute averages/logits to improve apparent fit.
No sampled native ast_value is a universal program equality or address/object proof.

An equal annotation address is diagnostic only. Upstream history reconstruction uses
act.bbl_addr and merges actions by location, while other hooks use state.addr. V19 did
not retain annotation class, read/write identity, event order, path/context instance or
actual instruction/statement provenance. Therefore this revision cannot establish an
exact event-level row binding, even if a group has one PC-coincident row. Event status
must stay unverified; semantic base/index assignment and v17 coverage remain unproven.

## Deliverables and validation

captures and before v20 implementation/retention: inspect native graph contribution paths.
Retain every byte-sized mem_loc target attributed to the target annotation address and
every candidate address root. Walk reverse value/data/operator edges, stopping at the
first original readout member on each branch. Retain path witnesses and excluded labels;
cycles/resource limits stay explicit. This is a native-graph frontier, not instruction
provenance, unique read/write event selection, a semantic role proof or new model readout.
Do not drop nonfrontier group rows or recompute historical candidate averages. Because
these are known developer inputs, matching frontiers provide mechanism evidence only.

Implement a small correspondence module, a snapshotting offline entry and focused
counterexample tests: location lifetime boundaries, ambiguity, changed identities,
same-looking names/IDs/values, row order and same-PC false positives. Keep group association
and exact-event outcome as distinct fields and denominators. All three queries and six
address-load occurrences remain visible, including unavailable associations. Twenty native
readout rows are not extra samples. Full validation precedes retained diagnostic output.

Record source/input copies, current/copy integrity checks, package versions, excluded
historical acquisition cost and forbidden framework imports. Offline diagnostic cost is
not deployment/scheduler benefit. Update OPM/status/evidence with what the data supports;
do not request a redundant WSL run solely to inspect already-retained data.

Use the resulting evidence to specify the smallest missing event-provenance capture
if an exact-event claim is needed. A uniquely storage-associated whole-variable group
may still be a valid coarse ranking feature; exact-event typing is not a prerequisite
for testing ranking-only information value. Keep that granularity explicit. Do not
change native TYGR annotation semantics, training features, layer capacities or readout
