# Development revision v12: location-only correspondence boundary

Declared before implementation and measurement on 11 November 2026. V11 completed on
Windows and WSL: the existing small menu does not establish neural information value,
and three retained target-semantic mapping proofs already imply their query decisions.
Keep all old sources/results and the frozen selector. This revision isolates correspondence
from property proving, using only the three existing compiled integration inputs.

## Inputs and strict non-goals

Use each fixed binary/query identity and frozen genuine TYGR raw export with its existing
function/CFA metadata and candidates. Do not load an operand plan, proof, object/index
anchor, source label or prior property result during mapping. Do not call angr,
BinaryChecker, state/solver construction, symbolic execution or any property checker.
No inference, compilation, model loading, training, downloads, installation, APIs or GPU.

Support only a small static AMD64 straight-line canonical frame subset, with explicit
ELF relocation coverage checks to ensure code bytes are stable. Establish the syntactic
CFA convention from push rbp / mov rbp,rsp, then track data-dependency origins through
register copies, loads of eight-byte aligned RBP slots and supported arithmetic. Map
only declared write-address dependencies to raw function/location records whose ranges
cover the relevant instruction/use site. Retain each prediction independently. Do not
choose or repair bindings by variable name, predicted type, score or expected result.

This is syntactic use-site correspondence, not a proof that a pointer names the declared
object, an index equals an entry input/expression, a write is inside bounds, or a path is
feasible. Keep candidate address contributions unlabeled by semantic base/index roles.
Unsupported instructions, frame changes, partial accesses, ambiguous locations, missing
dependencies or changed identities retain an unavailable/unknown query record. Never
remove such queries or turn their predictions into solver assumptions.

## Artifacts and validation

Create a distinct location-bundle schema that preserves raw exports, observed load/use
identities, static trace, binary/query/model hashes and the explicit absence of property
verification. A/B hide views; C shows per-prediction Top-1 labels; D shows the original
Top-K scores with conditional weights, not calibrated probabilities. Existing semantic
bundle readers must not silently accept the new schema. No old or new type view enters
the frozen selector in this revision.

Test static dependency identities, wrong/missing raw locations, score/name invariance,
overwritten uses, unsupported control flow and the absence of solver/property calls.
Then project the three existing raw inputs, retaining all attempts. Source snapshots and
raw/binary hashes precede the diagnostic. Any comparison with old semantic bindings is a
separate post-hoc identity check, never a runtime input. Report projection cost separately
from the original frozen export cost; do not call it fresh online acquisition or end-to-end
neural gain. The three inputs remain integration cases, not held-out evidence. All task
artifacts/caches remain on D.
